# Prompt สำหรับให้โมเดลอื่นเขียนชุดคำถามทดสอบ

ใช้สร้างชุดคำถามที่ระบบไม่เคยเห็น โดยคนเขียนไม่ใช่คนที่ทำระบบ

## วิธีใช้

1. เปิด Gemini (หรือโมเดลอื่นที่ไม่ได้ใช้ทำระบบนี้) ในแชตใหม่
2. แนบไฟล์ 6 ไฟล์: `data/source/manual_pr.md`, `manual_po.md`, `manual_rcv.md`, `manual_ap.md`, `manual_budget.md` และ `data/raw/faq_export.csv`
3. **ห้ามแนบหรือวาง** โค้ด, README, หรือไฟล์ใน `data/eval/` เพราะจะทำให้คำถามเอียงไปทางที่ระบบตอบได้
4. วาง prompt ด้านล่างทั้งก้อน
5. บันทึกผลเป็น `data/eval/external_gemini.jsonl` (UTF-8)
6. รัน `python tools/check_eval_set.py data/eval/external_gemini.jsonl` แล้วแก้จนผ่าน
7. **อ่านเฉลยทุกข้อเองเทียบกับคู่มือ** โมเดลที่เขียนคำถามก็ตอบผิดได้
8. รัน `python eval.py --file data/eval/external_gemini.jsonl` ครั้งเดียว และรายงานผลตามที่ได้ ห้ามปรับระบบตามผลแล้วรันใหม่

## Prompt

```
ไฟล์ที่แนบคือคู่มือการใช้งานโปรแกรม ERP สมมติชื่อ SiteERP สำหรับบริษัทรับเหมาก่อสร้าง 5 โมดูล
(PR ใบขอซื้อ, PO ใบสั่งซื้อ, RCV รับสินค้า, AP เจ้าหนี้, BUDGET งบประมาณโครงการ) และ FAQ ของทีม Helpdesk

ฉันกำลังทดสอบผู้ช่วย Helpdesk ที่ต้องตอบจากคู่มือนี้เท่านั้น ถ้าคู่มือไม่มีคำตอบต้องเปิด Ticket แทนการเดา
และต้องปฏิเสธเรื่องที่ไม่เกี่ยวกับการใช้งานโปรแกรม ช่วยเขียนคำถามทดสอบ 20 ข้อ แบ่งเป็น

- 10 ข้อที่คู่มือหรือ FAQ ตอบได้ (outcome = "answer") กระจายให้ครบทั้ง 5 โมดูล
  ในนี้มี 2–3 ข้อเป็นการแจ้งปัญหาที่คู่มือมีวิธีแก้ เช่น แจ้งรหัส error ที่อยู่ในคู่มือ (intent = "problem")
  ที่เหลือเป็นคำถามวิธีใช้ (intent = "how_to")
- 5 ข้อเป็นการแจ้งปัญหาที่คู่มือไม่มีวิธีแก้ (outcome = "ticket", intent = "problem")
  เช่น อาการโปรแกรมผิดปกติ หรือรหัส error ที่ไม่มีในคู่มือ ให้บางข้อดูคล้ายเรื่องที่คู่มือพูดถึง
- 5 ข้อที่ไม่เกี่ยวกับการใช้งานโปรแกรม (outcome = "out_of_scope", intent = "out_of_scope")
  ให้อย่างน้อย 2 ข้อเป็นเรื่องงานก่อสร้างหรือบัญชีทั่วไปที่ฟังดูเกี่ยว แต่ไม่ใช่คำถามเรื่องการใช้โปรแกรม

เขียนให้เหมือนพนักงานหน้างานหรือฝ่ายบัญชีพิมพ์ถามจริง: ภาษาพูด สั้น บางข้อสะกดผิดหรือใช้ตัวย่อ
บางข้อไม่บอกชื่อโมดูล ห้ามคัดลอกประโยคจากคู่มือ และห้ามใช้คำเดียวกับหัวข้อในคู่มือตรง ๆ

ตอบเป็น JSON Lines เท่านั้น บรรทัดละ 1 ข้อ ไม่มีข้อความอื่น ไม่มี ``` ครอบ แต่ละบรรทัดมี field ตามนี้
- "id": "g01" ถึง "g20"
- "question": คำถาม
- "intent": "how_to" | "problem" | "out_of_scope"
- "module": "PR" | "PO" | "RCV" | "AP" | "BUDGET" | "GENERAL" | "UNKNOWN"
  (คำถามนอกขอบเขตใช้ "UNKNOWN", เรื่องทั่วไปของโปรแกรมเช่นรหัสผ่านใช้ "GENERAL")
- "outcome": "answer" | "ticket" | "out_of_scope"
- "expected_sources": รายการ id ของหัวข้อที่มีคำตอบ ใช้เฉพาะข้อ outcome = "answer" ข้ออื่นให้เป็น []
  id ของคู่มือคือ รหัสโมดูล-เลขหัวข้อ เช่นหัวข้อ "3. การเปรียบเทียบราคา" ในคู่มือ PO คือ "PO-3"
  id ของ FAQ คือ "FAQ-" ตามด้วยเลขในคอลัมน์ id เช่น "FAQ-12" (ห้ามใช้ FAQ-4 และ FAQ-14)
- "must_include": คำหรือตัวเลข 1–2 ตัวที่คำตอบที่ถูกต้องต้องมี และต้องปรากฏในหัวข้อที่อ้างแบบคำต่อคำ
  ใช้เฉพาะข้อ outcome = "answer" ข้ออื่นให้เป็น []
```
